# Agent guidelines for Hiraku

These instructions govern AI-assisted development of the
`SwissDataScienceCenter/hiraku` repository.

For contributor documentation, see [CONTRIBUTING.md](CONTRIBUTING.md).

## Hiraku skill

The bundled Hiraku agent skill lives at:

`src/hiraku/resources/skills/hiraku/SKILL.md`

Use that skill when **operating Hiraku as a research tool**: creating tasks and
experiments, launching runs, inspecting evidence, or following Hiraku research
workflows.

Do not use the Hiraku skill as repository-development guidance. Changes to the
Hiraku implementation itself follow this file and `CONTRIBUTING.md`.

## Before changing code

Inspect the repository and existing work before implementing a change:

```bash
git status --short --branch
gh pr list
gh issue list
```

Preserve unrelated working-tree changes.

Keep changes focused on the requested behavior. Avoid unrelated refactors or
cosmetic changes.

Never use destructive Git operations to recover from an implementation problem
unless explicitly requested.

## Development environment

Use Python 3.11+ and `uv`.

Install the development environment with:

```bash
uv sync --all-extras
```

Use `uv` to modify dependencies and keep `uv.lock` synchronized. Do not edit the
lockfile manually.

## Validation

Run focused tests while iterating.

Before finishing a code change, run the relevant full checks:

```bash
uv run pytest
uv run ruff check .
uv run zensical build --clean
```

For packaging or release-related changes, also run:

```bash
uv build
```

Add regression tests for behavior changes and bug fixes. Do not weaken existing
tests merely to make a change pass.

## Documentation

Update documentation when changing:

* public Python APIs;
* CLI behavior;
* configuration or record formats;
* bundled examples;
* agent-facing behavior;
* files under `docs/`.

Build documentation with:

```bash
uv run zensical build --clean
```

Documentation sources are hand-written under `docs/` and `src/hiraku/`.
Generated `site/` output must not be committed.

## Generated and source files

| Path                      | Treatment                    |
| ------------------------- | ---------------------------- |
| `src/hiraku/**/*.py`      | source                       |
| `src/hiraku/resources/**` | bundled source/resources     |
| `docs/**/*.md`            | documentation source         |
| `tests/**`                | tests                        |
| `uv.lock`                 | generated by `uv`, committed |
| `site/**`                 | generated, do not commit     |
| `dist/**`                 | generated, do not commit     |

Do not commit credentials, virtual environments, caches, transient run data, or
build artifacts.

## Pull requests

Before opening or updating a pull request:

1. Check for related issues and pull requests.
2. Run the relevant validation commands.
3. Review the resulting diff.
4. Ensure documentation and tests match the changed behavior.

The human contributor remains responsible for AI-assisted changes.

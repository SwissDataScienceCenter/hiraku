# Heart Disease example

The project files copied by `hiraku example create heart-disease` are stored in
`src/`. See `docs/examples/heart-disease/README.md` in the Hiraku repository for
the complete walkthrough.

Add `--with-results` to include prepared research records and measured tracked runs.

Create the example project (Git is optional):

```bash
hiraku example create heart-disease --with-results
cd heart-disease
```

The results overlay includes four records and nine runs in `runs.csv`.
These were generated by the bundled training code on the processed Cleveland
dataset. Browsing them requires no training, credentials, or network access.

Query the prepared runs locally:

```bash
uv run hiraku leaderboard runs
```

To generate fresh runs directly during initialization instead of copying bundled
results, use `hiraku example create heart-disease --generate` in a new project.
This cannot be combined with `--with-results`, and existing projects are rejected.
Failed generation keeps the initialized project and any completed runs.

For two steps, opt into copying the generator:

```bash
hiraku example create heart-disease --with-generator
cd heart-disease
uv run --with hiraku python generate_results.py
```

Run the script in an environment containing Hiraku; from a checkout use
`uv run --project /path/to/hiraku python generate_results.py` instead.
The script refuses existing records or runs. Combine `--with-generator` and
`--generate` to run immediately and retain the script for reference.

Maintainers can export a fresh distributable overlay from the repository root:

```bash
uv run python src/hiraku/resources/examples/heart-disease/generate_results.py \
  --output /tmp/heart-disease-results
```

Initialization does not copy the generator unless `--with-generator` is given.
With `--output`, it trains in a temporary base example using that example's
pinned dependency environment, then exports only configuration, records and CSV.
The output directory must not already exist, and failed training publishes no
overlay. Dependency installation may require network access on the first run.

Each experiment uses seeds 1, 2 and 3. Logistic regression and random forest use
a validation fraction of 0.2; the nested forest check uses 0.3 to explore split
sensitivity, not to establish a directly comparable improvement. Records report
mean measurements without statistical significance or clinical claims.

Metrics are reproducible within the pinned environment; generated run IDs and
timestamps vary. Git attribution is preserved as reported by Hiraku's dispatcher
(unavailable for the isolated temporary project). The committed CSV was generated
with this script; subsequent training can append runs using the same schema. Its
runs predate the `duration` column, which is left empty for them.

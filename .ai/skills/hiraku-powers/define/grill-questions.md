# Grill questions

Ask only what grounding did not answer. One at a time, with a recommended answer.

0. **Deliverable.** Is this a Hiraku record, or a knowledge note that needs no
   run?
1. **Parent and purpose.** Which root does this serve, and what decision will
   its result inform? Should it be a child of the active experiment instead of
   the root?
2. **Hypothesis.** What exactly do you expect to change, and why? Rewrite it
   as a sentence that a run could contradict.
3. **Difference from siblings.** What does this change relative to existing
   children, and which sibling is the baseline?
4. **Metric and threshold.** Which root metric decides it, in which direction,
   and what margin counts as support, refutation, or inconclusive? What does
   each metric or symbol mean exactly?
5. **Comparability.** Which data split, budget, seeds, and evaluation protocol
   must match the baseline?
6. **Cheapest test.** Is there an existing entrypoint or argument change that
   tests this before any code change?
7. **Cost and risk.** Expected compute, time, data, or credential needs, and
   any limit the user wants enforced.
8. **Out of scope.** What should this record explicitly not try?
9. **Branch.** Is there a required branch, or does the nearest inherited
   `branch` apply?
